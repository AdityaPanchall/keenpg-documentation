    KeenPGO that never sleeps because we are keen for your Postgres¶

    keenPGO runs open-source PostgreSQL on Kubernetes and keeps it fast, safe and always on. You describe the database you want. keenPGO builds it, watches it, repairs it and keeps it that way.Provide a User Interface console with operator.

    Get started Installation guides

    At a glance¶

    • 100% open-source PostgreSQL

      Your data stays in standard PostgreSQL, and you can leave at any time with pg_dump.

    • Failover in seconds

      When a server dies, a replica takes over automatically and the old one heals and rejoins without anyone being paged.

    • Restore to any point in time

      Rewind your database to the moment before a mistake, not just to last night's backup.

    • Extensions included

      pgvector, PostGIS, pg_partman, pgaudit, pg_cron and more are ready to switch on.

    Always on¶

    • Self-monitoring clusters

      Every cluster watches its own health. Failed instances are detected and replaced without manual work.

      How failover works

    • Automatic failover

      A healthy replica is promoted to primary and applications reconnect to the same address.

    • Synchronous replication

      For data you cannot afford to lose, require a replica to confirm each write before it is acknowledged.

    • Rolling updates

      Settings changes, minor upgrades and node maintenance are applied one instance at a time to avoid downtime.

    Built to a standard

    Every keenPGO cluster is built and run to these targets: 5 seconds or less from a dead server to a new primary, with nobody paged.

    Backup and recovery¶

    • Point-in-time recovery

      Continuous archiving lets you restore to any second within your retention window.

    • Scheduled backups

      Define schedules and retention once. keenPGO takes care of the rest.

    • Off-cluster storage

      Keep backups outside the cluster, so they survive even if the cluster does not. <List supported storage types.>

    • Clone and restore

      Create a new cluster from a backup for testing, reporting or recovery.

      Backup and restore

    Security and compliance¶

    • Encrypted connections

      TLS protects data in transit between applications and the database.

    • User and access management

      Declare users, roles and database access in the cluster definition.

    • Audit logging

      Record who did what with pgaudit, to support compliance reviews.

    • Protected at every layer

      Security covers networking, credentials, storage and access.

      Security

    Built for builders¶

    Launch, scale, fail over and rewind with whichever tool suits your team.

    Declare a cluster and let the operator do the work.

    Kubernetes YAML
    apiVersion: <api-group>/<version>
kind: <ClusterKind>
metadata:
  name: orders
spec:
  instances: 3
    CLI
    # <Replace with your real CLI command>
keenpg create cluster orders --instances 3

    Leave proprietary licences behind¶

    Moving from a proprietary database to open-source PostgreSQL does not mean rewriting your business. A typical migration follows four stages:

    • 1. Assess

      review schema, code and dependencies

    • 2. Convert

      translate objects and application code

    • 3. Test

      validate behaviour and performance

    • 4. Cut over

      switch with minimal downtime

    Ask our team about a migration plan for your database.
